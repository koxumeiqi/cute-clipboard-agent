# 剪贴板历史栈与本地存储 - 界面设计

## 页面 / 窗口 / 入口

本 PRD 无直接 UI。用户可见入口来自后续历史面板、设置页和托盘清空命令。本单元提供 command 与事件，使这些入口能够查询、删除、清空和配置历史。

## 组件结构

无新增组件。前端仅新增 `shared/api/clipboard-api.ts` 中的历史 API 封装，供后续 `features/history-panel` 和 `features/settings` 使用。

## 状态

- 加载中：调用 `list_clipboard_history` 时由调用方显示。
- 就绪：返回倒序历史列表与设置。
- 空状态：列表为空时由历史面板显示。
- 错误：command 返回稳定错误字符串。
- 禁用 / 未授权：持久化关闭不禁用历史，只改为运行期内存历史。

## 交互

- 新剪贴板条目进入历史后，UI 订阅 `clipboard.created` 刷新列表。
- 单条删除后，UI 订阅 `clipboard.deleted` 或直接刷新列表。
- 清空后，UI 订阅 `history.cleared` 并进入空状态。
- 容量调整后，UI 重新查询历史并展示裁剪后的结果。

## 视觉与可访问性规则

本单元不新增视觉样式。后续历史面板必须避免在事件 payload 中展示完整文本来源，只通过显式查询展示用户主动打开的历史内容。

## UI BDD 场景

### 场景：历史面板刷新新条目
前置条件：历史面板已订阅事件。  
触发动作：收到 `clipboard.created`。  
预期结果：面板重新查询列表，新条目位于顶部。

### 场景：清空后显示空状态
前置条件：历史面板已有多条历史。  
触发动作：用户执行清空历史。  
预期结果：command 成功，面板列表为空。

## E2E 验证计划

### 自动化范围

当前无完整历史面板，使用 Rust 单元测试和调试 command 覆盖主要行为。

### 人工范围

在 Tauri 调试环境中复制文本，调用历史列表 command，确认新条目入栈；执行删除/清空后确认列表变化。

### 环境要求

Windows 桌面环境、Tauri dev 可启动、应用数据目录可写。

### 需要捕获的证据

命令调用结果、历史数量变化、图片文件删除前后状态。

## 人工验证清单

- [ ] 复制文本后历史列表顶部出现该文本预览。
- [ ] 连续复制超过容量后旧记录被淘汰。
- [ ] 删除历史后列表不再显示该项。
- [ ] 清空历史后列表为空。
- [ ] 关闭持久化后重启不恢复运行期历史。
