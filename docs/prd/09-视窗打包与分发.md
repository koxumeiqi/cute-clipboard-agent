# 09-视窗打包与分发

## 1. 单元概览

- PRD ID: 09
- 标题: 视窗打包与分发
- 状态: draft
- 来源 MRD: `docs/mrd.md`
- 是否开发单元: 是
- 核心交付: Windows 安装包、便携版压缩包、启动入口、发布说明和隐私可信分发信息。

## 2. 背景与目标约束

- 服务的产品目标: 让用户能够可信地安装、启动和退出应用。
- 目标用户/角色: Windows 桌面用户。
- 关联核心场景: 用户从 GitHub Releases 下载并安装，首次启动看到监听说明。
- 不包含的 MRD 范围: MVP 不实现自动更新、Microsoft Store、代码签名证书。
- 关键成功口径: 安装包和便携包可运行，发布说明明确监听和存储策略。

## 3. 范围

### 3.1 包含范围

- Windows 安装包。
- 便携版压缩包。
- GitHub Releases 发布产物。
- 安装后可从开始菜单启动。
- 首次启动展示剪贴板监听说明。
- 用户可选择是否开机启动。
- 应用可从托盘彻底退出。
- 发布说明包含隐私和数据存储说明。

### 3.2 不包含范围

- 自动更新。
- Microsoft Store。
- 代码签名证书。
- 多平台打包。

### 3.3 边界说明

本 PRD 只覆盖发布工程和分发信息。成功指标不单独成 PRD，但可作为发布验收口径。

## 4. 用户与场景

- 前置条件: MVP 功能已完成可构建。
- 触发条件: 开发者执行发布构建，用户下载并启动应用。
- 核心用户故事: 作为用户，我希望下载后能顺利安装或解压运行，并清楚知道应用会监听剪贴板。

## 6. 流程与状态

- 主流程: 构建应用 -> 生成安装包和便携包 -> 准备发布说明 -> 上传 GitHub Releases。
- 分支流程: 便携包启动 -> 不经过安装流程但仍执行首次告知。
- 异常流程: 构建失败 -> 输出错误并阻止发布。
- 状态变化: `dev_build`、`release_candidate`、`released`。

## 9. UX / 页面 / 交互要求

- 页面或界面: 安装流程、首次启动隐私告知、发布说明页面。
- 用户操作: 安装、启动、选择开机启动、退出。
- 反馈机制: 安装成功后可启动；首次启动清楚展示监听说明。
- 可访问性或易用性要求: 发布说明应明确“不上传剪贴板内容”和“如何暂停/清空”。

## 11. 风险与未决问题

### 11.1 风险

- 未签名安装包可能被 Windows 安全提示拦截，需要在发布说明中解释。

### 11.2 未决问题

- MVP 是否必须提供便携版，还是先提供安装包，待发布计划确认。
