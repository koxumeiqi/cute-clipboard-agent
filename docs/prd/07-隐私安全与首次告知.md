# 07-隐私安全与首次告知

## 1. 单元概览

- PRD ID: 07
- 标题: 隐私安全与首次告知
- 状态: draft
- 来源 MRD: `docs/mrd.md`
- 是否开发单元: 是
- 核心交付: 剪贴板监听首次告知、用户接受状态、本地优先说明、暂停记录、清空历史、持久化控制和 Agent 默认权限边界。

## 2. 背景与目标约束

- 服务的产品目标: 从第一阶段建立剪贴板隐私边界。
- 目标用户/角色: 复制内容中可能包含敏感信息的所有用户。
- 关联核心场景: 用户首次启动时理解应用会监听剪贴板，并可随时暂停或清空。
- 不包含的 MRD 范围: MVP 不实现自动识别密码、Token、银行卡号、身份证号。
- 关键成功口径: 用户知道监听目的和本地存储策略，能控制记录行为。

## 3. 范围

### 3.1 包含范围

- 首次启动或首次启用监听前展示剪贴板监听说明。
- 保存用户是否已接受告知。
- 默认本地存储，不上传剪贴板内容。
- 暂停记录能力与隐私文案。
- 清空历史能力与隐私文案。
- 本地持久化开关的隐私边界。
- Agent Bridge 默认不读取完整剪贴板内容。

### 3.2 不包含范围

- 敏感内容自动识别。
- 脱敏算法。
- 指定应用忽略列表。
- Agent 真实授权弹窗和二次确认完整流程。

### 3.3 边界说明

隐私模块定义告知、授权和控制边界；具体清空由存储模块执行，暂停由设置和监听模块执行。

## 4. 用户与场景

- 前置条件: 用户首次启动应用或首次开启剪贴板监听。
- 触发条件: 应用准备开始监听剪贴板。
- 核心用户故事: 作为用户，我希望在应用监听剪贴板前知道它会做什么，并可以停止记录或清空数据。

## 6. 流程与状态

- 主流程: 首次启动 -> 展示监听说明 -> 用户接受 -> 保存状态 -> 启动监听。
- 分支流程: 用户未接受 -> 不启动监听或保持暂停状态，具体策略待确认。
- 异常流程: 接受状态保存失败 -> 下次仍展示，且不应误启动监听。
- 状态变化: `notice_required`、`accepted`、`recording_paused`、`persistence_disabled`。

## 7. 依赖关系

### 7.1 上游依赖

- 设置模块保存隐私相关配置。

### 7.2 下游影响

- 剪贴板监听是否可启动。
- 历史存储是否允许持久化。
- Agent Bridge 可访问内容层级。
- Windows 分发说明内容。

### 7.3 共享实体

- `PrivacyState`
- `AgentPermissionLevel`
- `PrivacyNoticeAcceptedEvent`

## 8. 数据、事件与接口

- 涉及数据实体: `PrivacyState`。
- 关键字段: `clipboardNoticeAccepted`、`persistenceEnabled`、`recordingPaused`、`agentPermissionLevel`。
- 核心事件: `privacy.notice_accepted`、`agent.permission_changed`。
- API / 服务需求: 读取隐私状态、保存接受状态、切换记录状态、清空历史。

## 9. UX / 页面 / 交互要求

- 页面或界面: 首次告知弹窗或首次启动页、设置中的隐私控制。
- 用户操作: 接受告知、暂停记录、清空历史、关闭持久化。
- 反馈机制: 接受后开始记录；暂停后状态明确；清空后确认历史为空。
- 可访问性或易用性要求: 文案必须直白说明“监听剪贴板”“本地保存”“不上传”。

## 11. 风险与未决问题

### 11.1 风险

- 如果首次告知文案不清晰，会削弱用户对剪贴板监听的信任。

### 11.2 未决问题

- 用户拒绝首次告知时是否允许进入只展示桌宠但暂停监听的模式，待确认。
