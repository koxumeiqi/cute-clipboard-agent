# 06-系统托盘与应用生命周期

## 1. 单元概览

- PRD ID: 06
- 标题: 系统托盘与应用生命周期
- 状态: draft
- 来源 MRD: `docs/mrd.md`
- 是否开发单元: 是
- 核心交付: Windows 系统托盘入口、快捷菜单、后台常驻、打开历史/设置、暂停/恢复、清空历史和彻底退出。

## 2. 背景与目标约束

- 服务的产品目标: 应用在后台稳定运行，并提供非桌宠入口。
- 目标用户/角色: 需要长期后台记录剪贴板但希望可控退出的用户。
- 关联核心场景: 用户通过托盘暂停记录、打开历史或彻底退出应用。
- 不包含的 MRD 范围: MVP 不强制实现自动更新和 Microsoft Store。
- 关键成功口径: 托盘命令稳定执行，退出时停止监听并保存状态。

## 3. 范围

### 3.1 包含范围

- 系统托盘图标。
- 托盘右键菜单。
- 打开剪贴板历史。
- 暂停记录/恢复记录。
- 清空剪贴板历史。
- 打开设置。
- 退出应用。
- 应用后台常驻状态管理。

### 3.2 不包含范围

- 自动更新。
- 托盘通知中心。
- 多实例管理。
- Microsoft Store 集成。

### 3.3 边界说明

托盘模块负责命令入口和生命周期编排，不直接实现历史清空、设置保存或剪贴板监听。

## 4. 用户与场景

- 前置条件: 应用已启动。
- 触发条件: 用户右键托盘图标并选择菜单项。
- 核心用户故事: 作为用户，我希望应用在后台运行，同时能从托盘快速暂停、清空或退出。

## 6. 流程与状态

- 主流程: 应用启动 -> 初始化托盘 -> 用户选择命令 -> 发送托盘命令事件 -> 相关模块执行。
- 分支流程: 暂停状态下菜单显示“恢复记录剪贴板”；记录状态下显示“暂停记录剪贴板”。
- 异常流程: 清空历史失败 -> 保持菜单可用并通知 UI。
- 状态变化: `running`、`recording`、`paused`、`quitting`。

### 7.1 上游依赖

- 设置提供暂停状态。
- 历史存储提供清空能力。

### 7.2 下游影响

- 应用安装后行为和可信分发说明。
- 用户对后台常驻的控制感。

### 7.3 共享实体

- `TrayCommandEvent`
- `AppSettings.recordingPaused`
- 应用生命周期状态。

## 8. 数据、事件与接口

- 涉及数据实体: 设置状态、生命周期状态。
- 关键字段: `recordingPaused`。
- 核心事件: `tray.command`、`settings.clipboard_recording_paused`、`settings.clipboard_recording_resumed`。
- API / 服务需求: 创建托盘、更新菜单、打开窗口、隐藏窗口、退出应用。

## 9. UX / 页面 / 交互要求

- 页面或界面: Windows 托盘菜单。
- 用户操作: 右键、选择菜单项。
- 反馈机制: 暂停/恢复菜单文案同步；退出后进程结束。
- 可访问性或易用性要求: 清空历史和退出应用文案需要清晰。

## 11. 风险与未决问题

### 11.1 风险

- 关闭窗口后隐藏到托盘可能与用户“退出”预期冲突，需要明确行为和文案。

### 11.2 未决问题
