# 02-剪贴板监听与内容归一化

## 1. 单元概览

- PRD ID: 02
- 标题: 剪贴板监听与内容归一化
- 状态: draft
- 来源 MRD: `docs/mrd.md`
- 是否开发单元: 是
- 核心交付: Windows 剪贴板变化监听，读取文本、emoji、图片，生成统一 `ClipboardItem`，处理暂停、类型开关、去重和失败事件。

## 2. 背景与目标约束

- 服务的产品目标: 支持记录最近复制的文本、emoji、图片。
- 目标用户/角色: 需要找回最近复制内容的 Windows 用户。
- 关联核心场景: 用户复制内容后，应用自动记录并出现在历史面板。
- 不包含的 MRD 范围: 不支持 HTML 富文本、文件路径、URL 识别、代码片段分类、OCR。
- 关键成功口径: 文本、emoji、图片复制能稳定入栈；暂停记录时不入栈。

## 3. 范围

### 3.1 包含范围

- 监听 Windows 系统剪贴板变化。
- 读取文本、emoji、图片。
- 根据设置判断是否记录文本或图片。
- 将内容归一化为 `ClipboardItem`。
- 生成预览文本、图片路径、缩略图路径和内容 hash。
- 空内容、读取失败、类型不支持时不入栈。
- 栈顶重复内容默认不重复入栈。
- 应用自身写回剪贴板时避免重复记录。

### 3.2 不包含范围

- 自动识别代码、URL、文件路径等细分类型。
- OCR 和图片理解。
- 云端同步。
- Agent 分析。

### 3.3 边界说明

监听模块只负责读取和归一化，不负责最终持久化策略、历史查询 UI 或 Agent 处理。

## 4. 用户与场景

- 前置条件: 用户已完成首次监听告知，监听未暂停。
- 触发条件: Windows 剪贴板内容发生变化。
- 核心用户故事: 作为用户，我复制内容后，希望它自动出现在历史里。

## 6. 流程与状态

- 主流程: 剪贴板变化 -> 判断暂停和类型开关 -> 读取内容 -> 识别类型 -> 生成条目 -> 去重 -> 发送创建事件。
- 分支流程: 内容重复 -> 发送重复事件并忽略；类型禁用 -> 忽略。
- 异常流程: 读取失败 -> 发送 `clipboard.read_failed`，不入栈。
- 状态变化: `listening`、`paused`、`reading`、`normalizing`、`ignored`。

## 7. 依赖关系

### 7.1 上游依赖

- 隐私安全与首次告知提供监听允许边界。
- 设置与用户偏好提供记录开关。
- 事件总线提供事件分发。

### 7.2 下游影响

- 历史存储依赖归一化条目入栈。
- 历史面板依赖内容类型和预览展示。
- Agent Bridge 依赖剪贴板创建事件。

- `ClipboardCreatedEvent`

## 8. 数据、事件与接口

- 涉及数据实体: `ClipboardItem`。
- 关键字段: `id`、`type`、`preview`、`text`、`imagePath`、`thumbnailPath`、`hash`、`createdAt`、`updatedAt`。
- 核心事件: `clipboard.changed`、`clipboard.created`、`clipboard.duplicated`、`clipboard.read_failed`。
- API / 服务需求: 原生剪贴板读取、图片字节传递、文本读取、剪贴板写回抑制标记。

## 9. UX / 页面 / 交互要求

- 页面或界面: 暂无。
- 用户操作: 用户使用系统复制操作触发。
- 反馈机制: MVP 不强制弹出提示，历史面板打开时体现新增内容。
- 可访问性或易用性要求: 监听失败不应打断用户当前工作。

## 11. 风险与未决问题

### 11.1 风险

- Windows 剪贴板被其他程序占用时可能读取失败，需要可恢复。
- 图片格式和大小可能影响性能。

### 11.2 未决问题

- 图片缩略图生成放在监听模块还是存储模块，建议由存储模块负责。
