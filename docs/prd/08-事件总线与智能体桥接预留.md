# 08-事件总线与智能体桥接预留

## 1. 单元概览

- PRD ID: 08
- 标题: 事件总线与智能体桥接预留
- 状态: draft
- 来源 MRD: `docs/mrd.md`
- 是否开发单元: 是
- 核心交付: 应用核心事件定义、事件分发机制、内容访问分级、Agent Bridge 空实现、Agent 权限和上下文结构预留。

## 2. 背景与目标约束

- 服务的产品目标: 通过事件驱动为后续 Agent 能力预留扩展入口。
- 目标用户/角色: MVP 用户不直接感知，但受益于稳定架构和隐私边界。
- 关联核心场景: 剪贴板创建、历史更新、面板打开等事件可通知 UI 和 Agent Bridge。
- 不包含的 MRD 范围: MVP 不实现真实模型调用、Agent 对话、OCR、代码解释、总结。
- 关键成功口径: 各模块通过事件解耦，Agent Bridge 不读取未授权完整内容。

## 3. 范围

### 3.1 包含范围

- 定义核心 `AppEvent`。
- 实现或约定事件分发机制。
- 定义剪贴板、历史、桌宠、面板、设置、隐私事件。
- 区分元信息、预览信息、完整内容。
- Agent Bridge 订阅事件。
- Agent Bridge 空处理器。
- Agent 权限等级和上下文结构预留。

### 3.2 不包含范围

- 真实 Agent Runtime。
- 云端或本地模型调用。
- Agent 对话 UI。
- 自动分析和主动提醒。
- MCP Server 真实接入。

### 3.3 边界说明

事件总线提供模块解耦能力；Agent Bridge 在 MVP 中只做订阅和空处理，不能引入真实 AI 依赖。

## 4. 用户与场景

- 前置条件: 核心模块已发出应用事件。
- 触发条件: 剪贴板变化、历史操作、桌宠交互、设置更新、隐私授权变化。
- 核心用户故事: 作为开发者，我希望后续接入 Agent 时不用重写剪贴板和历史核心链路。

## 6. 流程与状态

- 主流程: 模块产生事件 -> 事件总线发布 -> 订阅者处理 -> UI/存储/Agent Bridge 更新。
- 分支流程: Agent 无权限 -> 只处理元信息或忽略。
- 异常流程: 单个订阅者失败不能阻断其他订阅者。
- 状态变化: 事件本身无持久状态；Agent Bridge 持有权限和上下文状态。

## 8. 数据、事件与接口

- 涉及数据实体: 应用事件、Agent 上下文、权限状态。
- 关键字段: `type`、`payload`、`permissionLevel`、`clipboardItemIds`、`appState`、`createdAt`。
- 核心事件: `clipboard.created`、`clipboard.deleted`、`history.cleared`、`pet.double_clicked`、`settings.updated`、`agent.permission_changed`。
- API / 服务需求: `publish(event)`、`subscribe(type, handler)`、Agent Bridge 事件处理入口。

## 9. UX / 页面 / 交互要求

- 页面或界面: MVP 暂无独立 UI。
- 用户操作: 间接来自各模块操作。
- 反馈机制: 通过订阅模块反馈。
- 可访问性或易用性要求: 不应因事件处理失败影响用户复制和恢复剪贴板。

## 11. 风险与未决问题

### 11.1 风险

- TypeScript 与 Rust 两侧事件定义不一致会导致运行期通信问题。
- 事件 payload 过大可能造成性能和隐私风险。

### 11.2 未决问题

- 事件总线是在前端、Rust 侧，还是跨 Tauri bridge 双层实现，待架构设计确认。
