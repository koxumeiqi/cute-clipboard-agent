# 05-设置与用户偏好

## 1. 单元概览

- PRD ID: 05
- 标题: 设置与用户偏好
- 状态: draft
- 来源 MRD: `docs/mrd.md`
- 是否开发单元: 是
- 核心交付: 设置页和配置持久化，控制历史容量、记录类型、桌宠行为、开机启动、持久化和暂停记录。

## 2. 背景与目标约束

- 服务的产品目标: 用户可控制剪贴板记录和桌宠行为。
- 目标用户/角色: 关注隐私、存储空间和使用打扰程度的用户。
- 关联核心场景: 用户暂停记录、调整容量或关闭图片记录后，应用行为立即变化。
- 不包含的 MRD 范围: MVP 不实现敏感内容自动识别、忽略指定应用、模型配置、MCP 配置。
- 关键成功口径: 设置变更可持久保存，并实时影响相关模块。

## 3. 范围

### 3.1 包含范围

- 历史最大容量。
- 是否记录文本。
- 是否记录图片。
- 是否显示桌宠待机动画。
- 是否允许桌宠自动移动。
- 是否开机启动。
- 是否启用本地持久化。
- 是否暂停剪贴板记录。
- 设置读取、保存和变更通知。

### 3.2 不包含范围

- 敏感内容保护规则配置。
- 忽略指定应用。
- 自动清理周期。
- Agent 授权详细设置。
- 本地模型、云模型或 MCP 服务配置。

### 3.3 边界说明

设置模块提供用户界面和配置状态，不直接实现剪贴板监听、存储裁剪、开机启动底层注册等具体能力；这些由相关模块响应设置变更完成。

## 4. 用户与场景

- 前置条件: 应用已启动，可从桌宠或托盘打开设置。
- 触发条件: 用户修改设置项。
- 核心用户故事: 作为用户，我希望能按自己的隐私和使用习惯调整记录内容、容量和桌宠行为。

## 6. 流程与状态

- 主流程: 打开设置 -> 读取当前配置 -> 用户修改 -> 保存配置 -> 发送 `settings.updated` -> 相关模块响应。
- 分支流程: 修改容量 -> 存储模块裁剪历史；暂停记录 -> 监听模块停止入栈。
- 异常流程: 保存失败 -> 显示错误并保留原设置。
- 状态变化: `loading`、`ready`、`saving`、`saved`、`error`。

## 7. 依赖关系

### 7.1 上游依赖

- 本地配置存储。
- 托盘或桌宠菜单打开入口。

### 7.2 下游影响

- 剪贴板监听响应记录类型和暂停状态。
- 历史存储响应容量和持久化状态。
- 桌宠响应动画和自动移动状态。
- 打包/生命周期响应开机启动状态。

### 7.3 共享实体

- `AppSettings`
- `SettingsUpdatedEvent`

### 7.4 相关 PRD

- 01-桌宠入口与桌面交互
- 02-剪贴板监听与内容归一化
- 03-剪贴板历史栈与本地存储
- 06-系统托盘与应用生命周期

## 8. 数据、事件与接口

- 涉及数据实体: `AppSettings`。
- 关键字段: `historyCapacity`、`recordText`、`recordImage`、`idleAnimationEnabled`、`autoMoveEnabled`、`launchAtStartup`、`persistenceEnabled`、`recordingPaused`。
- 核心事件: `settings.updated`、`settings.clipboard_recording_paused`、`settings.clipboard_recording_resumed`。
- API / 服务需求: 读取设置、保存设置、设置订阅、开机启动注册接口。

## 9. UX / 页面 / 交互要求

- 页面或界面: 设置页或设置面板。
- 用户操作: 切换开关、选择容量。
- 反馈机制: 保存成功、保存失败、暂停状态显著可见。
- 可访问性或易用性要求: 隐私相关设置文案要直白，避免用户误解。

## 10. 验收标准

| 编号 | 验收标准 | 验证方式 |
|---|---|---|

| AC-SET-07 | 关闭待机动画后桌宠停止动画 | 手工测试 |

## 11. 风险与未决问题

### 11.1 风险

- 关闭持久化时是否清理已有历史需要明确，否则可能产生隐私预期偏差。

### 11.2 未决问题

- 设置页是独立窗口、历史面板内入口，还是托盘触发的单独视图，待 UI 设计确认。
