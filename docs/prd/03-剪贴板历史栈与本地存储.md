# 03-剪贴板历史栈与本地存储

## 1. 单元概览

- PRD ID: 03
- 标题: 剪贴板历史栈与本地存储
- 状态: draft
- 来源 MRD: `docs/mrd.md`
- 是否开发单元: 是
- 核心交付: 最近剪贴板历史栈、本地持久化、容量裁剪、图片文件管理、查询、删除和清空能力。

## 2. 背景与目标约束

- 服务的产品目标: 管理最近复制内容，默认最多保留 20 条。
- 目标用户/角色: 希望找回最近复制内容的用户。
- 关联核心场景: 复制内容自动入栈，打开面板后按时间倒序查看。
- 不包含的 MRD 范围: 不实现云同步、多设备共享、团队协作。
- 关键成功口径: 历史入栈稳定、容量可控、清空彻底、本地优先。

## 3. 范围

### 3.1 包含范围

- 最新内容位于栈顶。
- 默认最多保存 20 条。
- 支持容量配置，建议 10、20、50。
- 文本历史保存完整文本和预览文本。
- 图片历史保存图片文件路径和缩略图路径。
- 持久化开关。
- 历史查询、单条删除、全部清空。
- 超过容量时移除最旧条目。
- 删除或清空图片历史时清理对应文件。

### 3.2 不包含范围

- 收藏和固定条目。
- 自动清理周期。
- 敏感内容自动识别。
- 云端备份。

### 3.3 边界说明

存储模块不负责监听剪贴板，也不负责 UI 渲染；只提供数据生命周期能力。

## 4. 用户与场景

- 前置条件: 剪贴板监听模块已生成有效 `ClipboardItem`。
- 触发条件: 收到新条目、删除请求、清空请求或容量变化。
- 核心用户故事: 作为用户，我希望最近复制内容可靠保存，超过容量后自动淘汰旧内容。

## 6. 流程与状态

- 主流程: 接收条目 -> 写入内存栈 -> 持久化 -> 检查容量 -> 淘汰旧条目 -> 发送事件。
- 分支流程: 持久化关闭 -> 只写入运行期内存。
- 异常流程: 图片保存失败 -> 条目不入栈或降级为读取失败，待实现时确认策略。
- 状态变化: `empty`、`ready`、`persisting`、`trimming`、`clearing`。

## 7. 依赖关系

### 7.1 上游依赖

- 剪贴板监听提供归一化条目。
- 设置提供容量和持久化开关。

### 7.2 下游影响

- 历史面板依赖列表、删除和清空接口。
- 隐私安全依赖清空和持久化控制。
- 打包分发需说明存储位置。

### 7.3 共享实体

- `ClipboardItem`
- `HistoryRepository`
- `ImageStorage`

## 8. 数据、事件与接口

- 涉及数据实体: `ClipboardItem`、应用配置、图片文件。
- 关键字段: `id`、`type`、`preview`、`hash`、`imagePath`、`thumbnailPath`、`createdAt`。
- 核心事件: `clipboard.created`、`clipboard.deleted`、`history.cleared`。
- API / 服务需求: `list`、`get`、`push`、`delete`、`clear`、`updateCapacity`、`saveImage`、`deleteImageFiles`。

## 9. UX / 页面 / 交互要求

- 页面或界面: 暂无。
- 用户操作: 通过历史面板、设置、托盘触发存储操作。
- 反馈机制: 存储操作结果通过事件通知 UI。
- 可访问性或易用性要求: 清空历史应真正清理本地数据，避免用户误解。

## 11. 风险与未决问题

### 11.1 风险

- 图片文件清理不彻底会造成隐私和磁盘占用问题。
- SQLite schema 过早固定可能影响后续类型扩展。

### 11.2 未决问题

- 文本历史和配置是否都放 SQLite，还是配置单独 JSON，待技术选型确认。
