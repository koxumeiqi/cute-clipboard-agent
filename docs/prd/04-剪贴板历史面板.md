# 04-剪贴板历史面板

## 1. 单元概览

- PRD ID: 04
- 标题: 剪贴板历史面板
- 状态: draft
- 来源 MRD: `docs/mrd.md`
- 是否开发单元: 是
- 核心交付: 历史面板 UI，展示最近复制列表，支持文本/emoji/图片预览、点击恢复、删除、清空和关闭。

## 2. 背景与目标约束

- 服务的产品目标: 用户能快速查看并恢复最近复制的内容。
- 目标用户/角色: 所有使用桌宠入口管理剪贴板历史的用户。
- 关联核心场景: 用户双击桌宠，打开历史面板，点击历史项恢复剪贴板。
- 不包含的 MRD 范围: MVP 不实现搜索、收藏、固定、类型筛选、快捷键打开。
- 关键成功口径: 用户能在 3 秒内打开历史并完成恢复操作。

## 3. 范围

### 3.1 包含范围

- 打开、关闭历史面板。
- 展示最近复制内容列表。
- 最新内容显示在顶部。
- 文本预览。
- emoji 原始渲染。
- 图片缩略图预览。
- 点击历史项写回系统剪贴板。
- 删除单条历史。
- 清空全部历史。
- 空状态展示。

### 3.2 不包含范围

- 搜索历史。
- 按类型筛选。
- 收藏或固定历史。
- 自然语言搜索。
- Agent 操作按钮。

### 3.3 边界说明

面板负责展示和触发用户动作，不直接处理底层持久化细节；写回系统剪贴板需要通过原生接口完成，并与监听模块协作避免重复入栈。

## 4. 用户与场景

- 前置条件: 桌宠入口或托盘可触发面板打开，历史存储可查询。
- 触发条件: 用户双击桌宠、选择托盘菜单或后续快捷键。
- 核心用户故事: 作为用户，我希望看到最近复制过的内容，并点击任意一条恢复到剪贴板。

## 6. 流程与状态

- 主流程: 打开面板 -> 查询历史 -> 渲染列表 -> 用户点击条目 -> 写回剪贴板 -> 显示成功反馈。
- 分支流程: 用户删除单条 -> 调用删除 -> 刷新列表；用户清空 -> 调用清空 -> 空状态。
- 异常流程: 写回失败 -> 显示失败反馈，不关闭面板。
- 状态变化: `closed`、`loading`、`open`、`restoring`、`empty`、`error`。

## 7. 依赖关系

### 7.1 上游依赖

- 桌宠或托盘提供打开入口。
- 历史存储提供查询、删除、清空。
- 剪贴板监听提供写回抑制协作。

### 7.2 下游影响

- 用户核心恢复体验。
- 成功指标中的 3 秒打开和恢复成功率。

### 7.3 共享实体

- `ClipboardItem`
- `HistoryPanelState`
- `HistoryItemSelectedEvent`

## 8. 数据、事件与接口

- 涉及数据实体: `ClipboardItem`、面板状态。
- 关键字段: `items`、`loading`、`error`、`lastRestoredItemId`。
- 核心事件: `panel.opened`、`panel.closed`、`history.item_selected`、`history.item_deleted`、`history.cleared`。
- API / 服务需求: 查询历史、删除、清空、写回文本、写回图片。

## 9. UX / 页面 / 交互要求

- 页面或界面: 历史面板。
- 用户操作: 点击历史项、删除、清空、关闭。
- 反馈机制: 写回成功、写回失败、删除成功、空状态。
- 可访问性或易用性要求: 文本预览不能溢出；图片缩略图要有稳定尺寸；删除按钮不能误触发恢复。

## 11. 风险与未决问题

### 11.1 风险

- 图片写回剪贴板的系统兼容性需要单独验证。
- 清空操作是否需要二次确认，MVP 可直接清空但有误操作风险。

### 11.2 未决问题

- 面板是独立窗口、浮层窗口还是和主窗口共用，待技术实现确认。
