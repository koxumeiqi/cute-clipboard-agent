# 开发规范

## 基本原则

- 先看 PRD，再动工程。
- 保持本地优先，剪贴板内容默认不上传。
- Agent Bridge 在 MVP 阶段只做空实现和权限预留。
- 事件 payload 默认只携带元信息、ID 和预览信息，禁止默认携带完整文本或原图数据。
- 模块之间通过共享契约、Tauri command 和事件通信，避免跨模块直接耦合内部实现。

## 前端规范

- 使用 React 和 TypeScript。
- 页面和功能按 `features/` 拆分，窗口入口按 `windows/` 拆分。
- 业务组件不直接散落调用 Tauri `invoke`，统一经 `shared/api/` 封装。
- 事件订阅统一放在 `shared/events/` 或对应 feature 的边界层。
- UI 组件优先放在 feature 内；只有多个 feature 真实复用时再提升到 `shared/ui/`。
- 设置、隐私、历史面板这类跨模块状态必须有明确 loading、error、empty 或 saved 状态。
- 桌宠窗口 UI 需要稳定尺寸和可拖拽区域，避免交互区域随内容抖动。

## Rust/Tauri 规范

- Tauri command 只做边界适配，不承载核心业务。
- 剪贴板、历史、设置、隐私、托盘、窗口、事件、Agent Bridge 分模块实现。
- SQLite 结构变更通过 `src-tauri/migrations/` 管理。
- 图片文件必须由 `image/` 模块统一保存和清理，历史删除和清空必须同步清理对应文件。
- 写回系统剪贴板时必须有自触发抑制机制，避免恢复历史后重复入栈。
- 单个事件订阅者失败不能阻断其他订阅者。
- 退出应用时需要停止监听、保存必要状态，并允许托盘彻底退出。

## 共享契约规范

- 事件名使用稳定字符串，例如 `clipboard.created`、`history.cleared`、`settings.updated`。
- `ClipboardItem` 至少覆盖文本、emoji 和图片三类 MVP 内容。
- `clipboard.created` 事件不携带完整内容，只携带 ID、类型、预览、hash、时间等必要信息。
- `AgentPermissionLevel` 默认最低权限，MVP 不允许 Agent 读取完整剪贴板内容。
- TypeScript 和 Rust 字段含义必须一致；如存在命名风格差异，需要在边界层明确转换。

## 隐私与安全

- 首次启用监听前必须展示监听说明。
- 未接受首次告知时，不应静默开始记录。
- 暂停记录时，新剪贴板内容不能入栈。
- 清空历史必须清理 SQLite 记录和图片文件。
- 关闭本地持久化后的历史恢复策略必须符合 PRD 或后续产品确认。
- 不在日志里输出完整剪贴板文本、原图路径以外的敏感数据或图片字节。

## 测试策略

- 事件总线、历史容量裁剪、设置持久化、隐私默认权限写单元测试。
- 剪贴板监听、写回抑制、图片保存和清理做集成测试或清晰的手工验证记录。
- 前端历史面板、设置页、首次告知、桌宠双击打开历史做交互验证。
- 发布前验证安装包或便携包、首次告知、托盘退出、清空历史。

## 文档维护

- 目录结构变化时同步更新 `docs/architecture/project-structure.md`。
- 新增或调整开发规则时同步更新根目录 `AGENTS.md` 和本文件。
- 影响用户隐私、存储位置、分发行为的改动需要同步 `docs/release/`。
